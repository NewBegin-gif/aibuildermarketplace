Claude Code writes the Mermaid, Miro draws it: an edit on the board changed the code, and a line of code changed the board

On the evening of 11 November 2026 we had Claude Code, Anthropic’s coding agent, write three Mermaid diagrams of a real system: the pipeline that turns an approved partner into a published review on this site. We put them into Miro’s new Mermaid diagrams on the free plan, then edited them on the board and in the code, broke the code on purpose and read it back out. One board, one evening, three diagram types: a case study, not a verdict on every setup.

Miro rendered all three Mermaid diagrams that Claude Code wrote as native Miro shapes. Renaming a box on the board rewrote the matching line of Mermaid, and a line we added to the code appeared as a new box. How we tested

  • A real system, not a toy. Claude Code wrote the Mermaid from what it had just read in our own pipeline: the onboarding queue, the research step, the honesty check that rejects any price not quoted in a source, and the publish gates. The flowchart has 16 boxes and 16 arrows, including one loop back and three dead ends.
  • Three diagram types. A flowchart (the onboarding pipeline), a sequence diagram (how a hands-on test travels from the browser to a live page, five participants and eight messages) and an ER diagram (partner, queue item, research file, dossier, test and review page: six entities, five relationships).
  • Miro’s free plan. An existing free Miro account in Chrome. For each diagram we placed a Diagram on the board, chose Build with code and put the Mermaid into the code panel, as Miro’s help page describes. We pasted the code with a scripted paste into the code panel rather than with the keyboard.
  • Checked in the code, not just on screen. After each change we read the Mermaid back out of Miro’s code panel and compared it with what Claude Code had written.

What the Claude Code half adds

The point of Mermaid in Miro is that the diagram stays text. Claude Code could describe our pipeline in a minute because it had just read the code, and because the result is Mermaid rather than a picture, the same text can go back into the repository next to the code it describes. What we did by hand on the board, rename a step and add one, is the kind of change an agent can make in the code instead. Miro’s help page says agents connected through Miro’s MCP server can also create, read and update these diagrams directly on a board.

Then through Miro’s MCP server: Claude Code on the board itself

Later that evening we connected Claude Code to Miro’s MCP server (https://mcp.miro.com/), signing in once through Miro’s OAuth page and choosing our team. After that Claude Code worked on the same board without anyone copying text.

  • Read back. Asked for the flowchart, the MCP tool canvas_read_as_svg returned the full Mermaid source, not just a picture. It arrives XML-escaped (--&gt; for -->), so an agent has to unescape it before saving it next to the code.
  • Create. A new four-box flowchart went onto the board through canvas_create_from_svg, with the Mermaid text wrapped in a diagram element. Read back, it was a native, editable Mermaid diagram, not loose shapes and arrows. Before the first create, Claude Code had to load Miro’s own instructions for the format through two helper tools.
  • Edit. Claude Code added the step “Claude checks the page live” to our existing flowchart with canvas_update_from_svg, sending only the old and new lines. Miro answered “Applied diff: 0 created, 1 updated”; the diagram kept its id, and opening it in Miro showed the new line in the code panel (lines 19 and 20 in the screenshot below).
  • One slip, ours. The first edit put the new step one box too early. A second edit moved it; nothing was lost, but an agent edits the text exactly as told, so check where it lands.

We did not see the change legend Miro mentions: Claude Code did not add one, and we did not ask it to. The code panel that stayed empty after our scripted paste filled straight away when we opened the MCP-edited diagram.

Flowcharts only, for now

Miro is upfront that visual editing works for flowcharts only, with state, sequence, class and ER diagrams marked “Coming soon” on its help page. That matched what we saw: the sequence and ER diagrams looked right, but every change to them has to go through the code. The same page notes that Miro lays the diagram out itself, so you cannot drag a shape to a spot of your choosing unless you switch the diagram to free-form, which cuts it loose from the Mermaid code.

What it costs

Nothing extra. If you want to try it, start from Miro’s Mermaid page: miro.com/mermaid (our affiliate link). The free plan’s limit of three editable boards applies, as covered in our Miro review.

What this test does not show

  • The MCP change legend and other MCP tools. We used Miro MCP to read, create and edit Mermaid diagrams only. We did not see the change legend, and did not try its sticky notes, tables, docs, comments or sharing tools.
  • Teams. One account, one browser: no real-time co-editing, comments or sharing with a second person.
  • Other diagram types and Miro AI. No class or state diagrams, no Sidekicks or Flows, no switch to free-form and no export.
  • Large diagrams. Our biggest diagram had 17 boxes; we did not test how auto layout copes with hundreds.
