What it means

Before you commit to a tool, export a few test records on day one and open the file: that is the only way to know what leaving will cost you.

Main limitation

These are the tools we tested ourselves, one account each; this is not a sample of the SaaS market.

Every SaaS tool makes it easy to get your data in. The question you only ask when you want to leave is whether you can get it out again, in a file you can use. In every hands-on test we put a few synthetic records into the tool, then try to export them, open the file, and where we can, import it back. This report adds up 102 of those exit tests.

In hands-on exit tests of 102 business software tools (2026-10-23 to 2026-11-06), AIBuilder Marketplace obtained an export file from 57 (56%); in 38 of those 57 files some of the test data was missing or changed, and 3 of 12 re-imports of an exported file went through without duplicates or altered data.AIBuilder Marketplace, Report 08, edition 2026-11-06. “No file in our session” means an export route exists or was tried, but no usable file reached us during the test: an error, a file that never arrived, or a step we could not complete. “No self-serve export” means the product, on the plan we tested, offered no way to export that data ourselves.

Of the 57 files we obtained, we opened and checked 56. In 38 some of our test data was missing or changed: a field with no column in the export, a description that lost its line breaks, a hidden list column that was left out. In 34 the file itself had a quirk you would have to deal with before another tool reads it, such as no header row, a title row above the headers, semicolons instead of commas, or IDs shown in scientific notation.

Could we put it back?

A re-import is the hardest part of the test, and we only ran it where the tool offers an import route for the same object. Of 12 re-imports: 8 worked, with caveats, 3 clean, 1 created duplicates. A re-import that “works” can still leave you with two addresses instead of one updated address, or every column to map again by hand; each case is described on the tool’s review.

What we are not claiming

This is not the SaaS market. These are the tools we review and could test ourselves, mostly software for small and mid-sized businesses.

One plan, one account. A paid or higher plan can export more, and an admin can sometimes request a full backup from support.

Our records, not a full backup. We export the few synthetic records we created, so attachments, history and settings are mostly outside this test unless the review says otherwise.

Not a verdict on the product. Friction is described, not scored. A tool can be excellent at its job and still make leaving hard.

Method

Each hands-on test seeds the tool with synthetic records from a fixed test kit (contacts, events, invoices, depending on the category). At the end of the test we look for the export route a normal user would find, export those records, and note the format. Where we opened the file, we check whether every test record and field came along and whether the file needs fixing first. Where the tool imports the same object, we import the export back with one changed value and check for duplicates and whether the change replaced the old value. The verdicts in this report are coded from the published exit-test record of each tool, and each verdict is backed by a literal quote from that record; the build stops if a quote is not found word for word. The underlying records are also in our agent API under measured.exit_test; nothing is retyped.
